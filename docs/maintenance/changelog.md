# 改訂履歴

## 1.2.10 — 2026年9月27日

- 小テーマページの参考リンクのうち到達できなかった2件を修正（WAICのリンク先をトップページへ、Socketを自動到達確認の対象外に）。
- 到達状態、チェック項目、回答例の変更なし。

## 1.2.9 — 2026年9月27日

- 25の小テーマページに「参考リンク」を追加。指針・標準、代表的なツール・サービス（出典で言及されているものは付記）、関連する要素技術を `build/references.json` から展開。
- 要素技術ページの参考リンクのうち到達できなかった7件を修正。有償規格など自動到達確認の対象外を明示。
- 到達状態、チェック項目、回答例の変更なし。

## 1.2.8 — 2026年9月27日

- 28の要素技術ページに「参考リンク」を追加。仕様・公式ドキュメントと代表的なライブラリ・ツールを `build/references.json` で管理し、各ページへ自動展開。
- 参考リンクの到達を週次で確認するワークフロー（`check:links`）を追加。
- 到達状態、チェック項目、回答例の変更なし。

## 1.2.7 — 2026年9月27日

- 「スキル」の呼称を「要素技術」に変更。「スキル定義」は「要素技術」、「スキルID」は「要素技術ID」、「スキル領域」は「領域」、「個人のスキルを評価する」は「個人の習熟度を評価する」、「個人のスキル評価記録」は「個人の習熟度評価記録」とし、ナビゲーション、書式、README、サイト説明を統一。URL、ファイル名、`css.basic` などのIDは変更なし。
- 出典のチェック項目にある「スキルマップ」「スキルセット」は原文のまま。
- 到達状態、チェック項目、回答例の変更なし。

## 1.2.6 — 2026年9月27日

- チェック項目の「望ましい回答例」を、見出しから本文と区別した囲み（ラベルと「架空の記入例」の注記付き）に変更。ページ内目次から回答例の見出しを除去。単一Markdownでは引用ブロックとして出力。
- 28スキルページに、スキルの説明（対象と評価する能力）を追加。
- 28スキルページから、Lv1〜Lv4の要約文を削除。
- 到達状態、チェック項目、回答例の変更なし。

## 1.2.5 — 2026年9月27日

- スキル定義の一覧ページに、領域ごとの28スキルの表（スキルID、評価対象または主な前提）を掲載。
- 28スキルページから「評価を記録する」の節と、判定方法への案内文を削除。
- 25のチェックリストページから、原典の収録方法を説明する冒頭の段落を削除。
- チェック項目の見出しを「1-1-2：学習と改善」の形式に変更し、本書の通し番号（No.001〜100、C001〜C100）と「原典」の表記を廃止。記録書式、記入例、改善ガイド、検索の項目指定も出典のIDに統一。各ページはスキルID、領域、評価対象または前提、Lv1〜Lv4の要約、Lv0〜Lv4の定義だけで構成。
- 到達状態、チェック項目、回答例の変更なし。

## 1.2.4 — 2026年9月27日

- チームチェックリストの各項目から、本書独自の「望ましい原文への回答：TRUE／FALSE」の行を削除。回答の方法は原典に従い、本書の追加は回答例と改善管理用の判定のみに整理。
- 到達状態、チェック項目、回答例の変更なし。

## 1.2.3 — 2026年9月27日

- チームチェックリストの原典が一般社団法人日本CTO協会「Webフロントエンド版DX Criteria（v202402）」であることを、ホーム、チェックリスト一覧、25の小テーマの各ページ、サイトのフッター、単一Markdownの冒頭、READMEに明示。
- 出典ページを改訂。原典のライセンス（CC BY-SA 4.0）と本書で加えた変更を記載。
- リポジトリ全体をCC BY-SA 4.0で提供することを明記し、`LICENSE` にライセンス全文を追加。
- チームチェックリストの分類と名称を原典の5つの大テーマ・25の小テーマ・4つの観点に変更し、各ページと項目に原典IDと観点名を併記。原典の補足説明（37項目）を収録。本書独自の判定方法の説明を削除し、原典の概要・ポリシーと構造・使い方へのリンクに置き換え。
- 到達状態、チェック項目、望ましい判定の変更なし。

## 1.2.2 — 2026年9月27日

- 公開方式を、リリースタグのpushから `main` へのマージへ変更。PRでは検査のみを行い、マージを契機に同じ検査を通して公開。
- タグ検証スクリプトと `test:release` を削除。旧版へ戻す手順をrevertのマージに変更。
- README、ARCHITECTURE、編集・検証・公開手順を新しい方式に更新。到達状態、チェック項目、望ましい判定の変更なし。
