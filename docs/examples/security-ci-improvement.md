# 記入例：PR／MRごとのセキュリティ検査を整備する

以下は、記録方法を示す仮の例です。特定のチームの実績を示すものではありません。

| 項目 | 記入例 |
| :--- | :--- |
| 関連チェック項目 | 2-3-1（セキュリティ・メトリクスの計測）：PRごとのSASTと、基準を満たさない変更の混入防止。 |
| 対象範囲 | 対象フロントエンドリポジトリのすべてのPR／MRと共有CI。 |
| 個人のスキル | 担当者の`web.security`は、別途確認した実装・検証の証拠によりLv2。 |
| チームの現状 | ローカルでは検査しているが、共有CIには設定がなく、未検査の変更をマージできる。 |
| 原文への回答・判定 | FALSE・未達。 |
| 原因・制約 | 共通設定と担当が未定義であり、CI設定を変更する権限の調整が必要。 |
| 行うこと | 検査対象と許容基準を決め、CIジョブ、マージ条件、失敗時の手順、例外管理を整備する。 |
| 担当と支援 | 開発担当者が実装し、基盤担当者が権限・CI設定、セキュリティ担当者が基準の確認を支援する。 |
| 完了条件 | 基準を満たす検証用PR／MRは通過し、許容基準違反と検査自体の失敗ではマージが停止する。別のメンバーが手順を使って原因を確認できる。 |
| 効果の確認 | 導入後4週間の対象PR／MRについて、検査の実行状況、検出内容、対応時間、例外の滞留を確認する。 |

この例では、まず環境・運用を整備する必要があります。担当者がCI設定を一度作成したことだけでLv4とは判定しません。個人の習熟度は、[スキル定義](../skills/index.md)の該当定義と本人の行動に照らして別に確認します。
