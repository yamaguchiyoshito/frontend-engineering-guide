# 記入例：Gitの習熟度を初めて評価する

以下は、[個人の習熟度評価記録](../templates/individual-assessment.md)の記入方法を示す架空の例です。特定の人物や実績を示すものではありません。フロントエンド開発に不慣れなメンバーが、基礎領域の要素技術から評価を始める場面を想定しています。

## 一回目：未評価として記録する

| 項目 | 記入例 |
| :--- | :--- |
| 対象者・要素技術ID | 開発メンバーA・`git.basic` |
| 対象業務・目標Lv | 既存画面の文言修正と軽微なスタイル修正を担当する。修正をブランチで行い、PRを自力で作成できる必要があるため、目標はLv2。 |
| 自己評価 | 未評価。ブランチとマージの用語が分からず、Lv0とLv1のどちらに当たるか判断できなかった。 |
| 確認後の判定 | 未評価。 |
| 根拠 | なし。Gitを使った作業の実績がない。 |
| 支援と制約 | 本人は別の職種から異動して1週間目。開発環境は用意されているが、リポジトリでの作業機会がまだない。 |
| 判定理由 | 実績がないため、基本的な課題を確認するまでLv0とは判定しない（[判定のルール](../guide/individual-assessment.md#判定のルール)の「未評価とLv0を分けます」に従う）。 |
| 次の到達条件 | [用語集](../guide/glossary.md)でリポジトリ、コミット、ブランチ、マージを確認し、[Git](../skills/foundation/git.basic.md)の「はじめの一歩」に沿って練習用リポジトリで操作する。2週間後に再確認する。 |
| 支援者・確認日・評価者 | 支援者：テックリードB（週2回のペア作業）。確認日：4月7日。評価者：B。 |

## 二回目：確認課題を経てLv1と判定する

| 項目 | 記入例 |
| :--- | :--- |
| 対象者・要素技術ID | 開発メンバーA・`git.basic` |
| 対象業務・目標Lv | 変更なし（目標Lv2）。 |
| 自己評価 | Lv1。手順書を見ながら、ブランチの作成、変更のコミット、マージまでを一人で実行できた。 |
| 確認後の判定 | Lv1。 |
| 根拠 | 練習用リポジトリの履歴（ブランチ2本、コミット6件、マージ2件）。実際の担当画面の文言修正で作成したPR 1件。 |
| 支援と制約 | 初回のコンフリクトは、Bの口頭説明を受けながら解消した。rebaseは未経験。 |
| 判定理由 | Lv1の定義「基本用語を説明し、手順書や他者の支援に沿って限定された課題を実行できる」を、練習用リポジトリの履歴とPRで確認した。コンフリクトの解消に支援が必要なため、Lv2の「指示を受けずに完了」には該当しない。 |
| 次の到達条件 | 手順書を見ずにブランチ運用を完了し、コンフリクトを自力で解消して理由を説明できること。次の担当画面の修正2件で確認する。 |
| 支援者・確認日・評価者 | 支援者：B。確認日：4月21日。評価者：B。次回確認：5月中旬。 |

この例では、一回目に用語が分からない段階でLv0を付けず、未評価として学習の入口を決めています。二回目は、本人が作った履歴とPRを根拠に定義と照合し、支援が必要だった範囲を明記して次の到達条件につなげています。
