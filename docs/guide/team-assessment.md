# チームの取り組みを確認する

## 原典に従う

[チームチェックリスト](../checklists/index.md)の100項目は、一般社団法人日本CTO協会の[Webフロントエンド版DX Criteria（v202402）](https://dxcriteria.cto-a.org/frontend)です。分類、項目の文面、回答の方法は原典に従い、本書では独自に説明しません。確認を始める前に、次の原典ページを読んでください。

| 原典ページ | 内容 |
| :--- | :--- |
| [Webフロントエンド版DX Criteriaの概要](https://dxcriteria.cto-a.org/e29172142f0f4eacbc17f3d94c8160d0) | 目的、対象、位置付け |
| [ポリシーと構造](https://dxcriteria.cto-a.org/90a7445d540148408343e83f4cbbecac) | 5つの大テーマ、小テーマ、4つの観点の構成 |
| [使い方](https://dxcriteria.cto-a.org/db7e371398c2464792dc25d79e573ba1) | アセスメントの進め方と回答の方法 |
| 各項目のページ | 本書の各項目にある「原文の参照先」から開けます |

## 本書で追加した内容

原典に含まれない、本書独自の追加は次の2点です。原典が定める評価方法として扱わないでください。

**望ましい回答例。** 望ましい状態を実現した場合の架空の記入例です。実施済みであることを示すものではありません。実際の回答では、実態、対象範囲、頻度、根拠資料を記載します。

**改善管理用の判定。** 原典への回答とは別に、改善を管理するために次の判定を記録します。

| 判定 | 使用する条件 | 次に行うこと |
| :--- | :--- | :--- |
| 達成 | 対象範囲で、望ましい状態を満たす証拠を確認できた。 | 運用を継続し、次回の確認時期を決めます。 |
| 一部達成 | 対象範囲や条件の一部で実施を確認できるが、全体としては満たしていない。 | 不足する条件と対象を明記し、改善を計画します。 |
| 未達 | 望ましい取り組みを実施していない、または問題の発生を確認した。 | 影響と原因を確認し、対応の優先順位を決めます。 |
| 未評価 | 判断に必要な情報や証拠を確認できていない。 | 情報の取得先と確認担当者を決めます。 |
| 対象外 | 項目の適用条件に該当しない。 | 対象外とする理由と、見直しの契機を記録します。 |

## 記録する

対象チーム、リポジトリ、環境、期間を[評価全体の対象範囲](../templates/assessment-scope.md)に記録し、項目ごとの原典への回答、判定、根拠を[チームの確認記録](../templates/team-assessment.md)に記録します。記録の書式は本書の追加です。原典に基づく集計や表示の方法は、原典の[使い方](https://dxcriteria.cto-a.org/db7e371398c2464792dc25d79e573ba1)に従ってください。
