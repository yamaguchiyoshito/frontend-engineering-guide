# 個人の習熟度を評価する

## 習熟度の共通定義

| 習熟度 | 到達状態 | 判定の基準 |
| :--- | :--- | :--- |
| **Lv0：未習得** | 基本的な概念と操作を、まだ身に付けていない。 | 確認課題で基本的な説明・操作ができず、実行には手順ごとの指示と確認が必要です。 |
| **Lv1：支援を受けて実行できる** | 基本用語を説明し、手順書や他者の支援に沿って、限定された課題を実行できる。 | 用意された例を変更し、指定された確認方法で結果を確認できます。課題全体の設計や例外への対応には支援が必要です。 |
| **Lv2：標準的な課題を自力で完了できる** | 要件が明確な通常の課題について、手段を選び、実装・検証・修正まで完了できる。 | 作業の各段階で指示を受けずに完了し、選んだ方法と確認結果を説明できます。 |
| **Lv3：複雑な課題を設計・改善できる** | 複数の制約や例外を含む課題を分解し、設計判断、原因分析、改善、他者のレビューができる。 | 複数案の利点と制約を比較し、品質・保守性・性能などへの影響を根拠とともに説明できます。 |
| **Lv4：チームで再現できる仕組みにできる** | 知識と実践を標準・共通部品・自動検証・教材などに落とし込み、他者が継続して活用できる状態を作れる。 | 他者の利用実績と、品質・工数・習得などの改善効果を確認し、仕組みを更新できます。文書を作成しただけでは該当しません。 |

## 初めて自己評価する方へ

フロントエンド開発に不慣れな方は、次の順で始めてください。

1. **基礎領域の5つから始めます。** 31すべてを一度に評価せず、[基礎領域](../skills/foundation/index.md)のWeb基礎、HTML、CSS、JavaScript、Gitを対象にします。担当業務で必要な要素技術は、評価者と相談して後から加えます。
2. **用語が分からない要素技術は未評価にします。** Lv0は、基本的な課題を実際に試した結果として付ける判定です。定義文の用語が分からない段階では未評価と記録し、各ページ冒頭の「前提となる用語」と[用語集](glossary.md)で語彙を確認します。
3. **「はじめの一歩」に沿って試してから再評価します。** 各要素技術ページの「はじめの一歩」は、Lv1へ向けて最初に学ぶことと、その入口となる参考資料を示しています。全要素技術の順路は[学習コンテンツ](learning.md)にまとめています。そこに書かれた課題を自分で実行できたら、作ったものを根拠として自己評価を記録します。
4. **根拠は作ったものと行動で残します。** 読んだ資料の量ではなく、作成したページ、コード、リポジトリの履歴、受けた支援の内容を記録します。[記入例：Gitの習熟度を初めて評価する](../examples/git-first-assessment.md)に、未評価から始めてLv1と判定されるまでの流れを示しています。

## 判定のルール

**要素技術ごとに評価します。** 全員に同じLvを求めず、担当業務に必要な対象の要素技術と目標Lvを先に決めます。目標Lvは業務上の必要性を表し、現在の習熟度とは別に記録します。

**上位のLvは下位の条件を含みます。** 下位の条件を満たし、該当Lvの行動を実証できる最も高いLvを付けます。一部の行動だけが上位に該当する場合は、満たしているLvを記録し、上位の実績と不足する条件を補足します。

**未評価とLv0を分けます。** 証拠がない、担当したことがない、確認機会がないという理由だけでLv0にしません。基本的な課題を実際に確認した結果、Lv1の条件を満たしていない場合にLv0と判定します。

**資料やツールの使用を認めます。** 自力とは、参考資料やツールを使わないという意味ではありません。公式資料、検索、AI、開発ツールを利用できます。本人が実装の理由を説明し、誤りを発見し、修正と検証を行えることを確認します。

**成果物と行動を併せて確認します。** 完成したコードだけでなく、設計判断、検証結果、指摘への対応、支援を受けた範囲も確認します。チーム全体の成果を、そのまま一人の能力の証拠にはしません。

**整数のLvを単純平均して判断しません。** 各Lvは到達状態の段階を表すため、平均値だけでは担当業務に必要な能力の不足を判断できません。必要な要素技術ごとの差と、チーム内で補完できる体制を確認します。

## 評価の手順

| 手順 | 実施内容 | 残すもの |
| :---: | :--- | :--- |
| 1 | 担当する業務と責任範囲を確認し、評価する要素技術と目標Lvを決めます。 | 対象業務・対象の要素技術・目標Lv・設定理由 |
| 2 | [要素技術](../skills/index.md)を読み、本人が成果物や実行した作業を基に自己評価します。 | 自己評価と根拠資料 |
| 3 | 評価者が実装理由、例外への対応、検証方法、受けた支援を確認します。証拠が不足する箇所は演習や追加説明で確認します。 | 確認した行動と支援の程度 |
| 4 | 基準と証拠を照合し、現在のLvまたは未評価を記録します。意見が分かれた場合は、不足する証拠と追加の確認方法を決めます。 | 判定・根拠・確認日・評価者 |
| 5 | 目標との差から次の実務課題や学習課題を選び、完了時の確認方法を決めます。 | 次の到達条件・支援者・確認時期 |
