## 5-2-1：メトリクスの計測

横断的な技術向上を図るチームや取り組みがある場合、ユーザー体験や生産性の向上など事業成果に繋がる指標を追跡している。

::: example
横断施策ごとに、業務完了率、利用者の所要時間、変更のリードタイム、手戻り工数など、事業成果につながる指標を設定しています。導入前後を比較する際は対象業務や規模の違いを確認し、導入・運用・学習コストも含めて評価しています。月次で効果を追跡し、継続・改善・終了を判断しています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/cc2f745eb7f244dc962ac0a42eb9ed11)

## 5-2-2：学習と改善

チームの生産性を向上するためのツールやプラクティスをおおよそ定期的（月ごと〜半年ごと）に調査して導入を検討、試行している。

::: example
四半期ごとに、開発上のボトルネックを起点としてツールやプラクティスを調査しています。小規模な試行で作業時間、品質、保守負担、費用を比較し、結果に基づいて導入を判断しています。採用後は手順と支援体制を整え、効果が継続しているか確認しています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/9a2a833a3dea4211813edbddfebbef10)

## 5-2-3：プラクティス

チーム内やチーム間で共有すべき取り決めやナレッジをコンテンツ化して蓄積している。

**補足**

口伝や個人の努力によって伝えるのではなく、明示的なコンテンツとして蓄積することで、現状の振り返りや認識の共有ができるようになる。新入社員や異動者に対するオンボーディングコンテンツとしての効果も期待される。

::: example
設計方針、開発手順、運用手順、設計判断、失敗事例を検索可能な場所に蓄積しています。文書には対象読者、適用範囲、管理者、最終更新日を記載しています。実装や運用の変更時に更新し、四半期ごとに古い情報と重複を整理しています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/bb5d39452e1149efbda798b4dca685aa)

## 5-2-4：アンチパターン

組織内の技術方針が定まっておらず、なし崩し的に採用技術の断片化が進んでいる。

::: example
標準技術、選定基準、例外を認める条件、判断責任者を組織の技術方針として定めています。各チームの採用技術を台帳で把握し、四半期ごとに差異と理由を確認しています。合理的な違いは認めつつ、理由のない重複導入や保守不能な分散には共通化・移行の計画を立てています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/23a2052725d4470cadde5fe336825390)
