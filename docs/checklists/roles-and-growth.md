# 職務定義

**出典：** [Webフロントエンド版DX Criteria](https://dxcriteria.cto-a.org/frontend)（一般社団法人日本CTO協会、CC BY-SA 4.0）  
**大テーマ：** 5. 成長できるチーム  
**小テーマ：** 5-3 職務定義

## 5-3-1：メトリクスの計測

スキルマップによって職能の可視化を行い、年次的（半年ごと〜年ごと）に内容を更新している。

::: example
職務に必要なスキル、習熟度の定義、判断に使う実務経験や成果物を定め、スキルマップで可視化しています。半年ごとに本人と上長が確認し、内容を更新しています。担当業務に必要な能力との差を明確にし、育成、業務配置、採用の計画に反映しています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/e73122dec9b2436d980313a21bb4b4cd)

## 5-3-2：学習と改善

フロントエンドエンジニアが何をどこまで受け持つのか、またその足りない部分はどうやって改善するのかを言語化・可視化している。

::: example
フロントエンドエンジニアが担当する設計、実装、テスト、性能、アクセシビリティ、運用などの範囲と、他職種との責任分界を文書化しています。不足するスキルや体制を可視化し、育成・ペア作業・専門家支援・採用の対応を計画しています。担当者と到達目標を定め、進捗を確認しています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/a28bc93644ac4da1a460fb6502e29c4d)

## 5-3-3：プラクティス

Webフロントエンド技術領域の技術選定に責任をもつ職務上の役割が任命されている。

**補足**

フルスタックにすべてを分けずに全部を包括する事を目標とした組織の場合は必ずしもWebフロントエンド専門の役職が必要とは限らないが、昨今の移り変わりが速い状況に対して、専門家を置くという事を検討しているかをポイントとして記述することとした。

::: example
フロントエンド領域の技術選定に責任を持つ役割を任命し、権限、対象範囲、説明責任を明文化しています。その担当者が選定基準と技術方針を管理し、関係者の意見と検証結果を踏まえて判断しています。不在時の代理と判断が分かれた場合の相談先も定めています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/a0a40a6eafbf4ccd9357c889df5d1468)

## 5-3-4：アンチパターン

ディレクションやデザインなど開発の隣接業務に圧迫されて、メンバー本来の職能に関する成長が阻害されてしまっている。

**補足**

こちらも5-3-3と同様、Webフロントエンド領域に閉じずに全てを実施するような組織は存在するとは思うが、昨今のフロントエンドの移り変わりの速さを勘案してこの項目を入れた。

::: example
開発、調整、デザイン支援、問い合わせなどの業務量を把握し、隣接業務の負担によって専門性を伸ばす機会が失われないよう配分しています。学習と難度のある開発に取り組む時間を計画に含めています。月次で負荷と成長目標を確認し、偏りがある場合は役割分担や支援体制を変更しています。
:::
