## 4-3-1：メトリクスの計測

計測可能なキャッシュヒット率について、定期的（月ごと〜半年ごと）に改善のためのアクションを検討している。

**補足**

ブラウザキャッシュなど基本的に計測できない対象を除き、CDNやサーバーサイド全般のキャッシュは、現状の設定がリアルユーザーにとって効果的かを観測すべきである。

::: example
CDNやサーバーなど、計測可能なキャッシュ層ごとにヒット率、応答時間、転送量、更新遅延を確認しています。月次で対象データや有効期間を見直し、改善案を検討しています。ヒット率だけを高めるのではなく、データの鮮度と利用者への影響も確認して設定を変更しています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/45d33ce7057c4c8cbb62a7c6dbff5c45)

## 4-3-2：学習と改善

ブラウザキャッシュやサーバーサイドキャッシュ、CDNなど各キャッシュ機能の特徴に応じて使い分けた設計をしている。

::: example
ブラウザ、CDN、サーバーの各層で、対象データ、有効期間、キャッシュキー、更新・無効化方法を定義しています。静的ファイルと更新頻度の高いデータを区別し、利用者ごとの情報が共有キャッシュから他者へ返らないよう設計しています。採用理由と設定を設計書に記録しています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/543f7c74e1fb44559e3e8dec4dce0e9f)

## 4-3-3：プラクティス

CDNキャッシュのパージ操作やデプロイによって、任意のタイミングで各種キャッシュを更新できる（古いキャッシュが参照されなくなる）仕組みになっている。

**補足**

急な情報の更新やアプリケーションの不具合を想定して、予め合意された時間内に適切に既存のキャッシュが無効化され、新しいキャッシュに置き換わるような仕組みであることを確認する。

静的ファイルについてはファイル名やパラメータにファイルのハッシュ文字列を付け加えるなどで常に一意なURLを作る(キャッシュバスティング)なども有効である。

::: example
CDNのパージ、サーバーキャッシュの無効化、静的ファイルのバージョン付きURLなどにより、更新後の情報へ切り替えられます。各キャッシュ層の失効条件と旧版が参照され得る時間を定義しています。緊急更新時の手順を用意し、再取得や画面再読み込みを含めて新版を利用できることを検証しています。
:::

[原文の参照先](https://dxcriteria.cto-a.org/9045515bb5a7464e848c65f4f6b97bfe)

## 4-3-4：アンチパターン

キャッシュの利用を設計時に検討しておらず、使う使わないの判断もなく一貫性のないキャッシュ設定が適用されている。

::: example
設計時にデータの鮮度、機密性、更新頻度、性能要件を確認し、キャッシュを使用するか判断しています。使用する場合は各層の設定と無効化方法を定義し、使用しない場合も理由を記録しています。設定はコードとレビューで管理し、環境や画面ごとに意図しない差異が生じる状態を防いでいます。
:::

[原文の参照先](https://dxcriteria.cto-a.org/ffcabe1203954b0b9282aeeaad0afc4b)
